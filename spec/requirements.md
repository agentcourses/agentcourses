# Requirement register

This register lists every rule that a schema builder, validator builder or runner builder must implement. It covers [the format](format.md), [execution](execution.md), [consent](consent.md), [record](records.md) and [identity](identity.md) contracts. Each row names where the rule came from, links its normative text, one or more concrete accepted cases and the rejected or warning cases that break it, and says who enforces it and who will prove it. A schema builder should start with rows whose enforcer is `schema`, and leave rows marked `markdown validator` or `runner` to other proofs. A *proof owner* named here is an assignment, not a claim that a proof has run: no schema, validator or runner proof exists yet. The normative pages are [format](format.md), [execution](execution.md), [consent](consent.md), [records](records.md) and [identity](identity.md).

**State words:** `resolved` rows have complete proposed text and linked cases. It does not mean the owner approved them. No row is `pending` now: the record contract closed the rows that waited for it, and the register's last section holds them.

**How to read a row:** each case link goes to one row of a case table. The row names a baseline, one change, the stage at which it is judged and the deciding rule. A row's *Invalid example* cell holds the rejected cases and, where the rule is advice, the warning cases that show the rule never invalidates a course. A row with several duties lists a case for each duty. Local-folder rows marked *proposed* await the owner's review.
