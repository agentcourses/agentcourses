A course is a folder of Markdown files, a few check programs and one rubric. This guide builds the smallest complete one, a course named `quickstart` that teaches a learner to build a one-file agent and explain it. The course page below declares the current format, checks and lesson order. The lesson and rubric includes supply teaching material; the program and fixtures let you try the command contract directly.

The course you write is addressed to the tutor, the agent that teaches it. Only each lesson's `## Goal` is read to the learner as written. The [course format](/specification/#format--lesson-headings) lists the headings a runner looks for.

<Aside type="caution" title="What you can run today">
The fixture commands below use Python locally. Schema and whole-course consumer support for the current declarations is still being implemented. The repository harness is an internal proof tool and does not yet validate courses written by this guide. There is no installable package yet, and the `/learn` command is not released.
</Aside>

## Before you start

Install Python 3.12 to try the check program. Choose any empty directory for the course itself. It is your course folder, and it is separate from the project a learner works in. Where this guide says "the course folder", use that directory.

Folder names matter: the folder name must equal the course's `name`, so the folder here is called `quickstart` ([course shape](/specification/#format--course-shape)).

<Steps>

1. ### Create the folders

   Run this in your chosen empty directory, which will hold the course folder.

   ```sh
   mkdir -p quickstart/lessons quickstart/tutor quickstart/scripts/fixtures/final-check/pass quickstart/scripts/fixtures/final-check/fail
   ```

   The layout is described in [the course layout](/specification/#format--folder-layout).

2. ### Write the course page

   Save this as `quickstart/COURSE.md` in the course folder. Its frontmatter names the course; its body is the page a learner reads first.

   ```markdown
   ---
   format: "1.0.0-rc.2"
   name: quickstart
   description: Build a one-file agent and explain it. For beginners.
   version: "1.0.0"
   license: Apache-2.0
   project: [own]
   checks:
     - id: final-check
       run: python "$AGENT_COURSE_DIR/scripts/final_check.py"
       verify: agent.py defines an agent
       timeout: 30
       network: false
     - id: agent-runs
       kind: observe
       verify: agent.py exists and defines an agent
   ---

   # Build a small agent

   You'll build a small agent.

   ## Outcome

   `agent.py`: an agent that passes `final-check`.

   ## Lessons

   1. [Meet the agent](lessons/intro.md)
   2. [Make the agent](lessons/make.md)
   3. [Finish and explain](lessons/finish.md)
   ```

   The `project: [own]` line means the learner works in the project they already have open. See [the project field](/specification/#format--project-field) for the other options.

3. ### Write the three lessons

   Save each file in `quickstart/lessons/` in the course folder. The file name is the lesson id, and the order of lessons is the order listed in `COURSE.md`.

   Together the lessons show two habits worth copying. The `make` lesson's `## Build` section is an instruction to the tutor, not to the learner.

4. ### Read the check declarations

   The course page already includes the following `checks` field. Keep it inside `COURSE.md` frontmatter; it declares one command check and one observe check ([check declarations](/specification/#execution--check-declarations)).

   ```yaml
   checks:
     - id: final-check
       run: python "$AGENT_COURSE_DIR/scripts/final_check.py"
       verify: agent.py defines an agent
       timeout: 30
       network: false
     - id: agent-runs
       kind: observe
       verify: agent.py exists and defines an agent
   ```

5. ### Write the check program

   Save this as `quickstart/scripts/final_check.py` in the course folder. A check runs with the learner's project as its working directory, so it reads `agent.py` by a relative path. It reads the file without running it.

   ```python
   """Check that the fixture project declares an agent without importing its code."""
   import ast
   import json
   from pathlib import Path

   path = Path('agent.py')
   try:
       tree = ast.parse(path.read_text(encoding='utf-8'))
       passed = any(
           isinstance(node, (ast.Assign, ast.AnnAssign))
           and any(isinstance(target, ast.Name) and target.id == 'agent'
                   for target in (node.targets if isinstance(node, ast.Assign) else [node.target]))
           for node in tree.body
       )
   except (OSError, UnicodeError, SyntaxError):
       passed = False
   print(json.dumps({
       'check': 'final-check',
       'status': 'pass' if passed else 'fail',
       'path': 'agent.py',
       'line': 1,
       'message': 'Agent declared.' if passed else 'No agent declaration found.',
       'fix': 'Define an agent variable in agent.py.' if not passed else '',
   }))
   raise SystemExit(0 if passed else 1)
   ```

6. ### Add the fixtures

   Every command check needs a project that passes and a project that fails ([rules every check follows](/specification/#execution--check-rules)). Save this as `quickstart/scripts/fixtures/final-check/pass/agent.py` in the course folder:

   ```python
   agent = object()
   ```

   Save this as `quickstart/scripts/fixtures/final-check/fail/agent.py` in the course folder:

   ```python
   value = None
   ```

7. ### Write the rubric

   Save this as `quickstart/tutor/finish.rubric.md` in the course folder. The rubric belongs to the final lesson and is never shown to the learner ([rubric grammar](/specification/#execution--rubric-grammar)). The [explain-back guide](/authors/explain-back/) explains how it is used.

   <ExampleCode example="quickstart" file="tutor/finish.rubric.md" lang="markdown" />

8. ### Add optional feedback

   Add this field inside `COURSE.md` frontmatter, before its closing `---`. It declares the only feedback the course may ask for ([declared only](/specification/#consent--declared-only)). Omit it to ask for none. A declaration never grants consent.

   ```yaml
   feedback:
     rating: at-end
     stuck: {after_failures: 3}
     questions:
       - id: next-step
         ask: Which topic would you choose next?
         options: [Tools, Checks]
   ```

9. ### Review the course

   Compare your frontmatter, lesson list, check references and rubric with the [format rules](/specification/#format--markdown-only-constraints). Current-format schema and whole-course validation are not available yet. No command here claims to validate the entire course.

10. ### Try the check against both fixtures

    This runs the program the way a runner would, with the project as the working directory. Run it from inside the course folder's parent directory, using a plain `python3`. It changes nothing.

    ```sh
    COURSE="$PWD/quickstart"
    cd "$COURSE/scripts/fixtures/final-check/pass"
    AGENT_COURSE_DIR="$COURSE" AGENT_COURSE_PROJECT="$PWD" python3 "$COURSE/scripts/final_check.py"; echo "exit $?"
    cd "$COURSE/scripts/fixtures/final-check/fail"
    AGENT_COURSE_DIR="$COURSE" AGENT_COURSE_PROJECT="$PWD" python3 "$COURSE/scripts/final_check.py"; echo "exit $?"
    ```

    The first project exits `0` and reports `pass`. The second exits `1` and reports `fail` with a path and a fix. The [checks guide](/authors/checks/) explains what each exit code means.

</Steps>

## How a runner will teach this course

When a learner takes the course, each lesson follows the same loop: the tutor says the Goal, builds with the learner, puts each call to the learner, runs the lesson's checks, reviews the results and, in the last lesson only, asks for the explain-back ([the teaching loop](/specification/#execution--teaching-loop)). While building, the tutor shows each change and says why, and rereads a file just before editing it so a hand edit by the learner is never overwritten ([building together](/specification/#execution--build-duties)). Write your lessons so the tutor can do all of this. The tutor may type the code, while the learner owns the decisions.

## What is not available yet

A public `validate`, `test` or `lint` command and a released `/learn` command are planned. They are **not available**, so nothing in this guide depends on them. The fixture commands above test only the program's pass and fail behaviour. They do not qualify a course, runner or host.
