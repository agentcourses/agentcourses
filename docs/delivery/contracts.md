# Contract resolution register

This register records how each open question about the Agent Courses candidate was resolved, why, and what an implementer should try first. Authors and schema builders read it to see which choices were made for them. It is the course contract's half of the candidate: questions that belong to the record contract stay pending in the last table until that theme lands. Every row marked "Proposed" is a semantic choice made by the drafter and waits for the owner's review on the pull request. No row here is approved by a link check, by plan acceptance or by an independent review; only the owner's recorded choice counts. Rows marked "Owner-decided" follow a decision the owner already made, and only their wording awaits review.

The rules themselves are in [format](../../spec/format.md), [execution](../../spec/execution.md) and [consent](../../spec/consent.md). Each is traced in [the requirement register](../../spec/requirements.md). The receipt choice that constrains settlement is in [the receipt experiment report](call-receipts.md).

**Source of the questions:** the [draft research](https://github.com/tutr-dev/tutr-strategy/blob/milestones/agent-courses-specification/docs/research/2026-10-19-agent-courses-1-0-draft.md), its nine-row conflict table and its open-question list, compared with the full frozen proposal where the extracted text was damaged.

**Candidate blockers versus later work:** a row is a candidate blocker when a schema, validator or runner builder cannot proceed without it. Stable-release qualification and external adoption are later and are named as such.

**Cases, not headings:** each example cell links to one concrete case, which names a baseline, one change and the rule that decides it. A resolution that carries several claims has a case for each claim. The local-folder row is new in this revision; it and the course-link-base row are the only rows added to this register.
